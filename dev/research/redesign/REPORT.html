Typing the inside of the pipeline: a redesign of tacit

Tacit's runtime contracts work. Its static promises mostly don't. After seventeen experiments and three rounds of review, the recommendation is a thin, layered library on narwhals. The core contracts the native Polars and PySpark frames people already write. Typed authoring sits on top as an option.

pyright 1.1.414mypy 2.4.0ty 0.0.89pyrefly 1.4.0narwhals 2.27.1ibis 12.0.0pandera 0.34.1pyspark 4.2polars 2.0

Summary

Today, tacit's static guarantees hold in pyright only.

  • mypy sees ibis and tacit as Any, because neither ships py.typed.
  • ty and pyrefly miss a forgotten cast, because an ibis mixin gives every ibis Table an unknown base class.
  • No checker catches a typo in a column name.
  • The README's own example fails pyright.

The runtime contracts are good. The rest of the design should keep them and make the static side real, without turning tacit into a second dataframe library.

Recommendation (revision 3)

  • Engine: narwhals stable.v2, with ibis still reachable as one of its backends. For data engineers on PySpark and Polars it is the better fit:
    • it runs on PySpark 4.2 and Spark Connect, which ibis 12 can't even be installed alongside;
    • it supports window functions on Polars;
    • it type-checks fully on all four checkers, including mypy;
    • it promises in writing never to break stable.v2.
    If the users turn out to be mostly SQL-warehouse analysts, staying on ibis remains a sound fallback, and is spelled out below.
  • Layer 1, the thin core: contracts on native frames.
    • Users keep writing native Polars or PySpark.
    • tc.tag(Orders, df) validates in one query and returns the same native frame, typed PolarsFrame[Orders] or SparkFrame[Orders].
    • @tc.step checks a step's inputs and outputs.
    • tc.names(Orders).amount gives a typo-checked column name for pl.col(...) and F.col(...).
    • This needs no typing facade and no wrapping. It is the FastAPI-style glue the project set out to be.
  • Layer 2, optional typed authoring.
    • DataFrame[S] over narwhals, backed by a 30-line stub generated from narwhals.
    • Typed columns through df.c.amount, and checked construction with Out.build, Out.extend, aggregate and join.
    • It is backend-portable.
    • Typing columns down to their value type needs a small tacit-owned facade, about 130 methods, because narwhals expressions carry no dtype. Start with names and structure; add value types only if teams want them.
  • Validation: one fused query, with pandera's checks as the check library. On Spark that is 6 jobs, against pandera's 40. Errors list every issue with counts and samples.
  • Fix five narwhals bugs upstream first. Three of them return wrong results silently. Run a 72-operation probe for each backend in CI.

Proposed design

Schemas, the same for both layers

import tacit as tc
from tacit import Column

class RawOrder(tc.Schema):
    order_id: Column[int] = tc.field(unique=True)
    customer_id: Column[int]
    order_ts: Column[datetime]
    status: Column[str] = tc.field(isin=["pending", "shipped", "cancelled"])
    amount: Column[float] = tc.field(ge=0)
    discount: Column[float | None] = tc.field(ge=0)      # nullable is spelled | None

class NetAmount(tc.Schema): net_amount: Column[float]
class Order(RawOrder, NetAmount): pass

Layer 1: contracts on native frames (the core)

Users write ordinary Polars or PySpark. tacit tags, validates and names. This is from e16-narwhals/examples/native.py, which runs and type-checks clean:

O, C = tc.names(Order), tc.names(RawCustomer)          # O.amount == "amount", typo-checked

@tc.step
def clean_orders(o: PolarsFrame[RawOrder]) -> PolarsFrame[Order]:
    kept = o.filter(pl.col(O.status) != "cancelled")
    return tc.tag(Order, kept.with_columns(
        (pl.col(O.amount) - pl.col(O.discount).fill_null(0)).alias(NetAmount.net_amount)))

@tc.step
def clean_orders_spark(o: SparkFrame[RawOrder]) -> SparkFrame[Order]:
    kept = o.filter(F.col(O.status) != "cancelled")
    return tc.tag(Order, kept.withColumn(NetAmount.net_amount,
        F.col(O.amount) - F.coalesce(F.col(O.discount), F.lit(0.0))))

orders = tc.tag(RawOrder, pl.read_parquet("orders.parquet"))   # validate: 1 query; returns a pl.DataFrame

  • Why it's cheap. The tags are declared as subclasses of the native frame classes, and at runtime they are the native object. Polars and PySpark annotate their methods as returning the concrete class, so any operation drops the tag. That makes "forgot to re-validate" a type error for free. The cost is re-tagging after a filter, with tc.tag(..., validate=False).
  • The limit. Polars Expr and PySpark Column carry no dtype, so value-level mistakes in native code are caught only at validation. The runtime catches them at the next tag or step, with counts and samples.

Layer 2: typed authoring on narwhals (optional)

For teams that want typed columns and backend-portable steps. This is from e16-narwhals/examples/t2nw.py, with 0 diagnostics on all four checkers:

def clean_orders(o: DataFrame[RawOrder]) -> DataFrame[Order]:
    kept = o.filter(o.c.status != "cancelled")                       # o.c.statu: error on all 4
    return Order.extend(kept, NetAmount.build(kept, net_amount=kept.c.amount - kept.c.discount.fill_null(0)))

def status_summary(o: DataFrame[Order]) -> DataFrame[StatusSummary]:
    by = o.group_by(Order.status).agg(orders=o.c.order_id.count(), revenue=o.c.net_amount.sum())
    return StatusSummary.conform(by.with_columns(share=nw.col("revenue") / nw.col("revenue").sum()))
    # returning `by` directly: error on all 4 (a LazyFrame is not DataFrame[StatusSummary])
  • What DataFrame[S] is. At runtime it is a nw.LazyFrame subclass, so nw.to_native, nw.concat and isinstance all work. The ibis design's as_table false positive is gone.
  • The 30-line generated stub. narwhals types every frame method as returning Self, so with_columns would claim to keep the schema. That would be a lie. The stub rewrites the 11 schema-changing methods to return a plain LazyFrame. Without it, "forgot to cast" is missed on all four checkers.
  • Results. 27/27 expected errors caught on pyright, mypy and pyrefly (ty 25/27), with 0 false positives. A raw frame passed where DataFrame[S] is expected is caught on all four; with ibis, only pyright caught it.

When to stay on ibis instead. If most users are SQL-warehouse analysts on BigQuery or Snowflake, ibis's breadth wins. In that case, use revision 2: DataFrame[S] as an ibis Table with the generated stub, E17's lean column layer, and pandera checks in one query. Pin ibis-framework<13 and a working sqlglot, and keep the exit plan. Everything in that design is prototyped (E13, E15, E17).

How much typing to own

This is the owner's question about the 8k generated lines. The answer differs by engine, and by which guarantees you actually want.

GuaranteeNeedsRuntime fallback if not typed
Column-name typos, wrong frame, forgot cast or tag, missing or extra output columnsSchema classes plus tags or DataFrame[S], and a small generated frame stub (30 lines on narwhals, 160 on ibis). No column facade.—
Wrong method for a type, value-family mismatch, int vs float in outputsA column facade. On ibis: a mechanical copy of ibis's own classes (about 1.8k generated lines plus a 52-line patch table, E17). On narwhals: a tacit-owned facade of about 130 methods, because narwhals has no per-dtype classes to copy.Caught while the pipeline is being built, before any query runs (E17: 10 of 11 planted bugs)
Nullability (nullable into non-null)A facade with nullability rules (E11: 8.3k lines on ibis, verified by execution)Caught only when data is validated. So validate step outputs by default.

Recommendation. Layer 1 owns no column facade at all. Layer 2 starts with names and structure. A value-type facade over narwhals is about 130 methods, hand-written or derived by execution on three backends, with a conformance test. Build it only if teams ask for it. The runtime already catches value-type mistakes before any data moves.

Column spellings

A free col("amount") can't be checked. A function's return type can depend only on its argument, not on which frame the result is later used with. Python has no "keys of this schema" operator. TypedDict works only because checkers special-case td["key"], and the TypedDict type is its key table. A schema class has no such table.

End-to-end experience

E15 built a complete e-commerce pipeline in the typed design. It has 2 sources, 8 steps, a join, an aggregation, a rank, a generic step, a raw-engine detour and a validated boundary. It was written on ibis; the narwhals port uses the same spelling with narwhals's API (e16-narwhals/examples/t2nw.py). It type-checks with 0 diagnostics on all four checkers. The full code is in e15-e2e/examples/e2e.py.

  • What it costs. A class per derived shape. build restates columns. .c appears everywhere. Typing ends at raw engine operations until you re-enter with conform. conform checks structure only, so NULLs pass it. A join on the wrong key of the same type is silent, exactly as in the plain engine.

  • Layer 1 is cheaper still. Native code with tags is the same length as plain Polars, plus one tc.tag per step.

Validation

Keep pandera as the check library and run its checks in one fused query.

  • pandera's checks are lazy expressions. tacit collects them before anything runs, reduces each to a failure count inside one aggregate, and fetches samples only for the checks that failed.
  • On ibis this matched pandera.validate on 682 of 685 cases (E10). Two differences are deliberate (true counts rather than capped ones, and a fallback without a count). The third is a pandera bug: empty tables fail validation.
  • On narwhals the executor is about 100 lines, and pandera's narwhals builtin checks plug in unchanged (E16).

  • Gaps on narwhals. There is no portable try_cast, so tacit can coerce types but can't count how many rows failed to coerce. narwhals schemas carry no nullable flag, so conform can't check NOT NULL structurally; only parse can.
  • pandera footguns found. Lazy inputs are validated schema-only by default, so bad data passes. coerce is ignored on the narwhals backend. unique is ignored on the native ibis backend.
  • Upstream path. pandera's spec #2401 moves pandera onto narwhals, so single-query execution belongs there. If it lands, tacit's executor can be deleted.

Review questions

Round 2

  1. "Isn't dropping pandera re-implementing every check?" Yes, and revision 1 understated it about 3×. Hence revision 2: keep pandera's checks and fuse their execution.
  2. "Doesn't a wrapper re-implement the engine's API?" It did. Revisions 2 and 3 keep the engine's real frame at runtime and generate only a small stub.
  3. "Why is ibis less maintained?" The lead maintainer: "the project lost most of its full time staff in September of 2024 due to layoffs." py.typed was removed by the maintainers themselves in 2023, because of 2,746 mypy errors. No part of the design depends on upstream patches.
  4. "Is it feasible?" Yes. Revision 3's sizing is in the roadmap.
  5. "Is the generated facade sound?" The hand-written one wasn't: 630 nullability lies. A derived one can be, but revision 3 makes the facade optional.

Round 3

  1. "Why not 100% parity with pandera?" tacit relies on pandera for what each check means, not for how checks are executed. The three differences are listed under Validation, and 684 of 685 verdicts agree.
  2. "Import time doesn't matter." Noted. That removed the main argument for a native validator.
  3. "How did you fuse pandera's checks?" A pandera check on ibis or narwhals returns an unexecuted expression. tacit unwraps it to a boolean column, applies pandera's own null rules, and puts (~ok).sum() for every check into one aggregate. It relies on two private attributes (_check_fn, _check_kwargs), guarded by the parity battery.
  4. "A functional col() like ibis's _?" A free col("x") can't be checked. Typed references on the schema class (Orders.amount) can, and so can name strings for native code. See Column spellings.
  5. "Show me an end-to-end example." See End-to-end experience. Runtime ergonomics stay close to the engine's own, because the frame is the engine's frame.
  6. "How are stubs generated? Is the pipeline fully typed?" Stubs are generated at tacit's release time against the pinned engine version. Users never run code generation. The pipeline is not fully typed: raw-engine islands remain, fenced by conform.
  7. "Pinning ibis is fine." Agreed. A pin on the major version, with the stub regenerated in CI, makes the stub exact. On narwhals, pin stable.v2.
  8. "Explore narwhals seriously." Done (E16), and it changed the recommendation.
  9. "Are the 8k lines necessary?" No. See How much typing to own.
  10. "Is removing __getattr__ the only way?" On ibis, an override works only on pyright. Inside df.c, typos are caught without any stub. On narwhals the problem doesn't exist, because narwhals frames have no column attribute access.
  11. "What's the point of tacit gen?" It would generate derived schemas (pick, drop, rename) without copy-paste. That's optional, and dropped from the plan. tacit infer, which generates a schema from an existing table, is more useful.

Runtime defects in 0.2 (E0, E4, E10):

  • cast() rejects NOT NULL columns and timestamp(6).
  • float | None silently means non-nullable.
  • @contract skips some annotations, and breaks on TYPE_CHECKING imports and on generics.
  • unique is not enforced.
  • Error messages lack sample values and the step name.

Worth keeping:

  • schemas as classes;
  • the parse / cast split;
  • strict and non-null defaults;
  • clear structural errors.

Roadmap

  1. Phase 0: fix what ships (0.2.x, no API break)

    • Ship py.typed.
    • cast() becomes NOT NULL- and timestamp-aware.
    • X | None means nullable.
    • @contract: lazy hints, raises on annotations it can't enforce, supports generics.
    • Errors include counts, samples and step names.
    • Docs are honest about which checker supports what.
    • Typecheck CI on all four checkers.
    • Pin ibis-framework<13 and a working sqlglot.

  2. Phase 1: the thin core on narwhals (0.3)

    • Schemas with Column[T] declarations.
    • tag, step and names for Polars, PySpark, DuckDB and ibis frames.
    • Fused validation with pandera checks as the library; structured errors; filter_valid.
    • File the five narwhals bugs.
    • Per-backend operation probe in CI.
    • About 3–4 weeks; the native-tag prototype exists.

  3. Phase 2: typed authoring (0.4, then 1.0)

    • DataFrame[S] over narwhals with the generated stub; df.c; build, extend, aggregate, join, generic steps.
    • Names and structure first.
    • A value-type facade (about 130 methods, conformance-tested on three backends) only on demand.
    • About 3–5 weeks.

  4. Phase 3: tools for teams and agents

    • describe, infer, diff.
    • ODCS and JSON Schema export.
    • Multi-table collections.
    • Agent guide and llms.txt.

Migration from 0.2.

  • Schemas map mechanically: x: float becomes Column[float], and Nullable() becomes | None.
  • ibis users can keep their ibis code. An ibis Table is a native frame to Layer 1, so tc.tag(Orders, ibis_table) works.
  • Typed authoring moves from ibis syntax to narwhals syntax.

Risks and decisions

Risks

  • Silent backend bugs in narwhals. Three found in one experiment. Mitigations: upstream fixes first, the per-backend operation probe in CI, and a documented support table.
  • Private narwhals attributes. DataFrame[S] uses three of them (_with_compliant, _compliant_frame, _level). Pin stable.v2 and test against narwhals main.
  • Private pandera attributes in the fused executor. The parity battery is the guard, plus the upstream proposal.
  • SQL warehouses. The sqlframe path is young. Route BigQuery and Snowflake through ibis as a narwhals backend.
  • Coercion and nullability are weaker on narwhals: no failure counts on coercion, and no structural NOT NULL check.

Decisions for the owner

  1. Engine. narwhals with ibis reachable (recommended for PySpark and Polars users), or stay on ibis (for warehouse analysts).
  2. Scope of 1.0. Layer 1 alone, or Layers 1 and 2.
  3. Value-type facade. Skip for now (recommended), or build the roughly 130-method narwhals facade.
  4. Validation. Fused execution with pandera checks (recommended), or plain pandera.
  5. The CLAUDE.md rule against type-checking examples. Revisit it: examples are now clean on all four checkers, which makes them the regression test for the library's core promise.
