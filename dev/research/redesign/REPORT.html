Typing the inside of the pipeline: a redesign of tacit

Tacit's runtime contracts work well. Its static promises mostly don't hold. This report measures both, describes what the ideal API would look like, and explains why Python can't express all of it yet. It then proposes a design, now prototyped, that gets every column reference checked by pyright, mypy and ty without plugins.

pyright 1.1.414mypy 2.4.0ty 0.0.89pyrefly 1.4.0ibis 12.0.0pandera 0.34.1Python 3.13

Summary

Tacit was designed when coding agents were weaker and the type-checker landscape was mostly pyright. Re-measured on today's tools, the runtime half holds up and the static half largely does not:

  • Only pyright enforces tacit's types.
    • mypy: neither tacit nor ibis ships py.typed, so mypy sees Any everywhere.
    • ty and pyrefly: ibis defines a mixin conditionally, which gives ty and pyrefly an Unknown base for every Table. A forgotten cast() passes silently.
  • No checker catches a typo in a column name. df.sepal_lenght is accepted everywhere, because DataFrame[S] inherits ibis's catch-all __getattr__.
  • The flagship examples fail pyright. The README's own quick example produces 4 errors. A docs-style pipeline written by an agent produced 7.

Recommendation

  • Make the schema class the typed frame. class Orders(tc.Frame) wraps an ibis table; it does not subclass it. Columns are declared as Column[float], Column[str | None] and so on. Every column access is then name-checked and type-checked, nullability included.
  • Let construction carry the contract. An output frame's constructor is a statically checked projection, with helpers for the common shapes (extend, aggregate, join). A function that returns NetOrders can only return something that has the right columns. @contract shrinks to an optional @tc.step for data validation and error context.
  • Own a small ibis-native validator instead of pandera. It runs one query on success and two on failure, instead of 16–30. It is 2.6–7.4× faster, cuts about 2 s from import tacit, and reports counts and sample values.
  • Keep ibis, but stop exposing its typing to users. A generated, tacit-owned column facade absorbs ibis's annotation gaps. Two one-line fixes go upstream.
  • Accept the language limits and work around them. Output schemas cannot be inferred (S + {"score": float}), so steps name their outputs, with small "delta" mixins and codegen for pick/drop/rename. If PEP 827 lands (3.16 at the earliest), these collapse into type aliases.

Where tacit stands

What to keep

  • Schemas are Python classes. Anyone can use go-to-definition, find-references, diffs and inheritance. This is the right foundation, and agents find schemas without extra context files.
  • The parse / cast split. Untrusted data gets coerced and validated. Trusted data gets a check that costs nothing. Teams understand this immediately.
  • Strict by default, non-nullable by default. These are the right defaults for production pipelines.
  • Runtime structural errors are excellent. In the trial, every runtime-detectable bug was caught, with messages that named the schema and the boundary.
  • Library, not framework, and backend-portable through ibis.

The view from a team

Picture a company with forty engineers and a few hundred pipelines, more and more of them written or modified by coding agents. What they need from a contract library:

  1. Refactors that can't silently break someone else. Renaming or retyping a column in a shared schema should light up every downstream use, across repositories. Today that works only for whole-schema mismatches, and only in pyright. Column-level uses are invisible.
  2. Feedback in seconds, not after a warehouse job. Agents in particular iterate on whatever the type checker and tests tell them. A mistake that surfaces only at runtime, after a Spark job or a BigQuery bill, is the most expensive kind. The single most agent-friendly property a library can have is that wrong code fails the type check.
  3. The same answer in every checker. Teams standardise on mypy, editors run Pylance, and new projects pick ty. A guarantee that holds in only one of them isn't a guarantee.
  4. Cheap validation with useful reports. Validation should cost one scan, not one per check. Failures should name the step, the column, how many rows, and examples. Teams should be able to quarantine bad rows rather than fail the whole run.
  5. Contracts other teams and tools can read. Schemas should be exportable (JSON Schema, ODCS), diffable for breaking changes, and inferable from an existing table.
  6. One obvious way to do things. Today there are two styles of @contract. One of them is a type error, and it is the one in the README. Agents copy the README.

The ideal API

Set the language aside for a moment. The best library for this job, for humans and agents alike, would read like this:

class Orders(tacit.Table):
    order_id: int = key()
    status: Literal["pending", "shipped", "cancelled"]
    amount: float = field(ge=0)
    discount: float | None

# output schema inferred from the body; nothing restated
def net(o: Orders) -> Orders & {"net_amount": float}:
    return o.with_columns(net_amount=o.amount - o.discount.fill_null(0))

# row-polymorphic: any table with an int id, same table out
def dedupe[S: {"id": int}](df: Table[S]) -> Table[S]: ...

# join output inferred, collisions reported statically
enriched = orders.join(customers, on=Orders.customer_id == Customers.customer_id)

Should we leave ibis? Narwhals is a typed, multi-backend API, but on DuckDB, PySpark and ibis it is lazy-only, it is a subset of the expression API, and it has no schema-typed frames. Polars-only libraries such as dataframely would cost us every SQL engine. Nothing found buys enough to justify a rewrite. The wrapper design also keeps the door open: because users no longer touch ibis types directly, a native Polars or PySpark backend could later sit behind the same Frame and Column API.

Proposed design: tacit-next

This is what the E8 prototype implements (e8-prototype/src/tacit_next, about 1,300 lines plus a generated stub). The user guide written for the second usability trial is e8-prototype/GUIDE.md.

Frames and columns

import tacit_next as tc
from tacit_next import Column

class Orders(tc.Frame):
    """Orders as delivered by the order service."""
    order_id: Column[int] = tc.field(unique=True)
    order_ts: Column[datetime]
    status: Column[str] = tc.field(isin=["pending", "shipped", "cancelled"])
    amount: Column[float] = tc.field(ge=0, description="gross, EUR")
    discount: Column[float | None]                       # nullable is spelled | None
    price: Column[Decimal] = tc.field(dtype="decimal(12, 2)")

orders.amount                   # Column[float]   (hover shows exactly this)
orders.amount.mean()            # Scalar[float]
orders.status.mean()            # error on all 4: no mean() for Column[str]
orders.discount.fill_null(0)    # Column[float | None] → Column[float]
orders.order_id / 2             # Column[float]; int, float and Decimal are kept apart
  • Why a wrapper, not a subclass. Any __getattr__ that a checker can see disables typo detection, and subclassing ir.Table inherits one. Wrapping is the only design where typos are caught (E2, section B). The raw table is one hop away at orders.ibis.
  • Why Column[T] keyed by Python types. One generic type gives readable hovers, separates int from float, and puts nullability in the type, so fill_null narrows it and assigning a nullable expression into a non-null column is a static error on all four checkers. Statically it is a generated stub with self-type overloads per value family. At runtime it is the plain ibis expression, so nothing is wrapped.
  • Why tc.field(...). It works with dataclass_transform on every checker. It also carries the description, the physical name and the dtype. Annotated[Column[float], tc.ge(0)] still works for reusable aliases.
  • Name collisions. A column named like a Frame member (filter, ibis, …) raises at class creation, with the fix in the message: tc.field(name="filter").

Boundaries: parse and cast

orders = Orders.parse(con.read_csv("orders.csv"))   # coerce + validate: 1 query, +1 only on failure
orders = Orders.cast(con.table("orders"))           # names + type families, no query, NOT NULL-aware

With nominal frames, a subclass is assignable to its parent, so NetOrders can go where Orders is expected. The rules follow from that. At an input boundary, the table must have at least the declared columns, and tacit projects it down to exactly those, so the body sees an exact schema. Construction and output are strict. extra="forbid" makes inputs strict too.

Construction is the contract

class NetAmount(tc.Frame): net_amount: Column[float]     # the delta
class NetOrders(Orders, NetAmount): pass

def add_net(o: Orders) -> NetOrders:
    return NetOrders.extend(o, NetAmount(net_amount=o.amount - o.discount.fill_null(0)))
    # missing / extra / wrong-type delta column: error on all 4
    # Customers.extend(o, ...): error on all 4 (Into[Self]: NetOrders must subclass type(o))

def daily(o: Orders) -> DailyRevenue:
    day = o.order_ts.date()
    return DailyRevenue.aggregate(by=[day, o.status])(
        day=day, status=o.status, orders=o.order_id.count(), revenue=o.amount.sum())

def with_country(o: Orders, c: Customers) -> OrderCountry:
    j = tc.join(o, c, on=lambda o, c: o.customer_id == c.customer_id)
    return OrderCountry(order_id=j.left.order_id, country=j.right.country, amount=j.left.amount)
  • The constructor is a checked projection. dataclass_transform takes parameter types from the column descriptor's __set__, so every checker flags missing, unexpected and wrongly typed columns. A function annotated -> NetOrders can only return something built this way, so the "forgot the column" class of bug becomes a type error.
  • Why aggregate(by=...) is explicit. The prototype also accepts reductions directly in the constructor, as an implicit GROUP BY. But forgetting a .sum() then quietly turns that column into a grouping key. With by=, the same mistake raises not_a_reduction. Document the explicit form.
  • Joins expose typed left and right views over prefixed columns, and the output constructor names every column, so collisions cannot happen by construction.

Reusable steps

# same frame in and out; columns passed as typed handles
def latest_per_key[F: tc.Frame](df: F, key: Column[Any], ts: Column[datetime]) -> F:
    return df.filter(tc.row_number().over(group_by=key, order_by=ts.desc()) == 0)

latest = latest_per_key(orders, key=orders.customer_id, ts=orders.order_ts)   # -> Orders

# "any frame with an event_ts": a mixin column set as the bound
class HasEventTs(tc.Frame): event_ts: Column[datetime]
def recent[F: HasEventTs](df: F, since: datetime) -> F:
    return df.filter(df.event_ts >= since)

Validation and errors

Orders.parse: 2 issues for Orders
  - amount: constraint ge(0) failed; 3 rows; e.g. ['-33.74', '-1.0', '-5.5']
  - status: constraint isin(['pending', 'shipped', 'cancelled']) failed; 1 row; e.g. ['refunded']

There is a single tc.ValidationError, with .issues: a list of structured records (code, column, expected, actual, count, samples). The optional @tc.step adds the step name, runs data checks with validate=True, catches raw tables passed by untyped callers, and supports TypeVar bounds and F | None. Annotations it can't enforce raise instead of being skipped. It resolves hints lazily, with a frame registry for names imported under if TYPE_CHECKING:.

Results. Every checker reported zero diagnostics on the correct pipeline. The agent rated its confidence that "the type checker had my back" at 7/10: 9/10 for names, types and frames. The points it lost show where the design has to go next. Each friction point below has a proposed fix (details in e9-agent-trial/FINDINGS.md):

  • Nullability can't be narrowed after a filter. After filter(status == "completed"), completed_at is still nullable. Proposed fix: col.assume_not_null(), recorded on the frame and verified when the output is validated, so it is a checked assertion rather than a cast.
  • Reductions over nullable columns claim to be non-null. A group where every value is null yields NaN. Proposed fix: make these reductions return Scalar[T | None]. E8 had dropped None to avoid noise; E9 shows the sound version is needed.
  • No duration arithmetic. datetime - datetime is untyped. Proposed fix: add Column[timedelta] with total_seconds() to the facade.
  • Column handles passed to generic steps aren't tied to the frame. The language can't express that a handle must come from the frame being passed. Proposed fix: catch ibis's relation error and re-raise it as a ValidationError that names the step and parameter.
  • The guide overstated which errors are ValidationError. Fixed in GUIDE.md.

Known limits of the prototype

  • Interop false positives. Passing a typed column into raw ibis APIs (orders.ibis.filter(col), ibis.desc(col)) is flagged by pyright and ty. The facade derives from ir.Value, because deriving from ir.Column would bring back the Unknown base. Workaround: use the Frame's own methods, or tc.as_ibis(col).
  • The facade is owned surface. About 55 methods are typed per value family, generated by tools/gen_facade.py into a 1,073-line stub. Methods outside it fall back to ibis's own annotations.
  • Class-level references are unsound. Orders.amount is Column[float] statically but a Deferred at runtime. Either give them a distinct Ref[T] type or drop class access.
  • Joins are basic. There is no join-of-join scope, and outer joins don't make right nullable in the types.
  • Raw tables slip past three checkers. A raw ir.Table passed where a Frame is expected is still missed by mypy, ty and pyrefly until the two upstream fixes land. The runtime catches it.

Validation engine

E4 benchmarked pandera's ibis backend against a 150-line native validator. The test schema had 10 columns, 9 checks and 7 non-nullable columns, run on DuckDB with 2 vCPUs. The native validator computes nulls, every check, uniqueness and try_cast failures in one aggregate() query. It fetches samples with a second, bounded query only when something failed.

  • Failures get expensive with pandera. It fetches every failing row, plus one boolean per row of the table, into pandas, so failure cost is O(N) in data movement. Every query also recompiles the expression and, over a CSV view, re-reads the file.
  • Import time. import tacit takes 3.2 s, of which 2.7 s is pandera.ibis (pandas alone is 1.2 s). Without pandera it is about the cost of import ibis: 1.1–1.3 s.
  • Lazy validation. Checks can also be fused into the user's eventual query, as a filter that calls the engine's error() function. It avoids the extra pass and fails fast, but it validates only the rows a query reads. Offer it as an opt-in mode, not the default.
  • Remote engines widen the gap. These are single-machine DuckDB numbers. On a remote warehouse, going from 16 round trips to 1 matters more, not less.

Agents and teams

The largest agent-friendliness gain is already in the design: wrong code fails the type check, on whichever checker the agent's harness runs, with messages like "RawOrder" has no attribute "statu"; maybe "status"?. Roadmap

  1. Phase 0: fix what ships (0.2.x, no API break)

    • Ship py.typed. Document follow_untyped_imports for mypy.
    • Make cast() ignore nullability and timestamp precision. Make X | None mean nullable.
    • @contract: cache the signature and the target schema (128 → 4 µs); resolve hints lazily; raise on annotations it can't enforce; support TypeVar bounds.
    • Include counts, sample values and the step name in error messages. Enforce or reject unique.
    • Fix the README and docs: show the returns= form, and state honestly which checker supports what.
    • CI: run tests/typechecking on pyright, mypy, ty and pyrefly.
    • Housekeeping: cap polars<2 until ibis 13; require pandera>=0.31; do a trial docs build on Zensical before Material reaches end of life (2026-11-05).
    • File the two ibis fixes.

  2. Phase 1: validation engine (0.3)

    • Native one-query validator with tacit's own Check constructors.
    • Structured ValidationError.issues.
    • filter_valid soft validation.
    • Opt-in lazy guard mode.
    • Pandera becomes optional or is removed. Import time falls by about 2 s.

  3. Phase 2: typed frames (0.4, then 1.0)

    • Frame, Column[T] (generated facade), field, construction, extend, aggregate, join, @step.
    • Close the E9 gaps:
      • sound nullable reductions;
      • assume_not_null(), as a checked assertion;
      • Column[timedelta];
      • a distinct Ref[T] type for class-level references;
      • tc.left_join with nullable views;
      • relation errors wrapped with the step name.
    • Keep Schema and DataFrame[S] for one minor release as a deprecated shim.
    • Provide a codemod. The mapping is mechanical: x: float → x: Column[float]; Annotated[T, Nullable()] → Column[T | None]; DataFrame[S] → S.

  4. Phase 3: tools for teams and agents

    • describe, infer, gen --check, diff.
    • ODCS and JSON Schema export.
    • sample().
    • Multi-table collections with cross-table rules.
    • Agent guide and llms.txt.

Risks and decisions

Risks

  • ibis health. There has been no release since 12.0.0 (2026-02-07). Human commits fell from 512 in the prior year to 87 since. A 13.0 is planned, with Polars 2 and DuckDB 2, and Polars 2.0 already breaks one ibis 12 code path. Mitigation: the facade isolates users from ibis typing, and CI should run against ibis main before 13.0 ships.
  • Facade maintenance. The stub is generated, but someone owns the list of typed methods. Users hit false positives on methods outside it until they are added.
  • A breaking change in the schema syntax. This is the most visible cost. It is mitigated by the codemod and a one-release shim.
  • Checker churn. ty is still in beta, so type-check snapshot tests will move.

Decisions for the owner

  1. Accept the breaking schema syntax: Column[float] instead of float.
  2. Replace pandera with the native validator. Keep pandera Check objects only as an optional input format, if at all.
  3. Revisit the "no type checking on examples" rule in CLAUDE.md. With tacit-next, the examples type-check cleanly on all four checkers. Running the checkers on them becomes the regression test for the library's core promise.
  4. Choose how to handle class-level column references: a distinct Ref[T] type, or drop them.
  5. Decide whether to add pyrefly to the supported set. It worked as well as mypy in every experiment.
