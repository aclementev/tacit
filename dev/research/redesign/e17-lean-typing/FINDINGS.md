# E17 — Can a leaner column-typing layer replace the 8.3k-line derived facade?

> The E17 subagent (Opus) returned this report as text. The main session saved it here and checked `out/summary.txt` against the table below. `tools/run_all.sh` rebuilds all 12 configurations.
> Environment: ibis 12.0.0, pyright 1.1.414, mypy 2.4.0 (`follow_untyped_imports`), ty 0.0.89, pyrefly 1.4.0.

## Short answer

**Yes. L2 ("ibis's own types, cleaned") replaces the 8.3k-line facade, giving up only static nullability.**
- It catches every other bug class that E6 and E9 showed matters, the same way on all four checkers.
- It has 0 false positives on the three examples.
- Its cost is about 1.8k lines generated by a mechanical copy (no execution probing), a 52-line patch table, and 68 hand-written lines.

**L1 ("names only") is not enough.**
- It cannot check the value family of `build(...)` arguments.
- It is blind on ty and pyrefly with stock ibis.
- It produces 8 false-positive lines on the examples on pyright, mypy and pyrefly.

**The 160-line Table stub is still needed today.** Once ibis merges its two one-line fixes, the stub only buys "`df.anything` is an error".

## Layers

**L1** (`overlays/l1/tacit_thin/_column.pyi`, 59 hand-written lines)
- `Column[T].__get__` uses self-type overloads, so `Column[float]` resolves to `ir.FloatingColumn`.
- pyright and mypy ignore an overloaded `__set__` when synthesizing the `dataclass_transform` `__init__`, and mypy reports "Unsupported `__set__`" (`probes/p1_overloaded_set.py`). So `build` parameters cannot be per-family without codegen.
- L1 therefore uses `__set__(value: ir.Value | T | Deferred)`, which checks only names and literals.

**L2**
- `tools/gen_cols_stub.py` (388 lines) generates `_ibis_cols.pyi`: 1,819 lines, 30 classes, 1,364 members, copied from ibis's annotation strings with `inspect`.
- The MRO is cleaned: mirror Column classes subclass the real, clean ibis Value class of their family.
- One mechanical rule: on a Column receiver, a returned `XValue` becomes `XColumn`.
- A phantom `_Fam[T]` marker on each family lets a single non-overloaded `__set__(value: _Fam[T] | T | Deferred)` check families. A two-level marker fails on pyright and mypy (`probes/p2_phantom_marker/`), so Numeric members are flattened into each family class.
- **Patch table** (52 lines, 278 sites):
  - comparisons accept literals (ibis #11966-style);
  - `isin`/`notin` accept lists;
  - `between` accepts literal bounds;
  - `fill_null(0)`;
  - same-family reductions and window functions return `Self`;
  - `ifelse` accepts literals;
  - `sum`, `mean`, `std`, `var` and `cumsum` keep a family;
  - int∘int stays int, Decimal∘int stays Decimal, and int or Decimal `/` gives float.
- `_column.pyi`: 68 hand-written lines.
- The Table stub is regenerated with `--facade mirror`, which widens 52 parameters.

**L3** is E11's derived facade (8,345 lines). It reproduces E13's results.

## Is the Table stub necessary?

**Stock ibis, no stub:**
- mypy loses forgot-cast and most wrong-frame cases.
- ty and pyrefly lose forgot-cast.
- `df.anything` is accepted on all four checkers.

**Patched ibis, no stub:** everything is caught on all four checkers except `df.anything`.

**There is no stub-free substitute.** Overriding `__getattr__` (`probes/p0_getattr_override.py`) works on pyright only.

**Conclusion:** keep the 163-line generated stub until the two upstream fixes ship. After that it is optional.

## Recommendation

**Adopt L2 plus the generated Table stub.** That is about 2.0k generated lines from two mechanical generators and about 120 hand-written lines, with no execution probing.

**What L2 gives up compared with L3:**
1. **Static nullability.** Nullable-into-non-null becomes a validation-time error, so tacit should validate step outputs by default, or at least run a cheap NOT NULL count.
2. **Execution-checked soundness.** L2's patch claims are not verified by running them. A wrong claim surfaces loudly at construction, never as wrong data. A 20–30 assertion test of the patch table closes most of this gap.
3. **Hover precision.** Users see `NumericColumn` rather than `Column[float]`. Column handles must be annotated `tc.AnyCol` or with the mirror class.
4. **`bool` as a subtype of `int`** stays a hole, as in L3.
